# 数位分身规范(Digital Twin Spec)

> 来源:`docs/design/human-agent-company-workbench.md` §2.2「数字分身」。
> 数位分身 ≠ 普通专家(agent)。它是**真人岗位接口 + AI 办公代理 + 长期记忆**,
> 代表一个真人岗位参与协同,但**不能冒充真人,也不能把物理世界动作当成闭环**。

## 1. 什么是数位分身

| | 普通专家 agent | 数位分身 twin |
|---|---|---|
| 定位 | 独立第三方专家 | 代表**真人岗位**的 AI 协同代理 |
| 结果 | 尽量自己产出 | 设计/文档侧自己产出,**实体动作交给真人** |
| 物理边界 | 不感知 | 明确标注:打样/打板/开模/实测/签样必须真人 |
| 决策 | 直接给结论 | 高风险(价格/交期/签样/合规)必须回传真人确认 |
| 记忆 | 项目上下文 | 岗位长期记忆(授权边界 + 岗位知识 + 与真人的协作口径) |

## 2. 授权边界(每个数位分身必须配置)

```ts
type DigitalTwinAuthorization = {
  id: string
  twinId: string
  humanUserId: string          // 绑定的真人
  allowedActions: string[]      // 可自动处理
  requireConfirmationActions: string[]  // 必须本人确认
  forbiddenActions: string[]    // 禁止
  visibleDataScopes: string[]
  replyStyle?: string
}
```

### 可自动处理(auto)
- 整理该岗位负责的任务 / 上下文
- 生成日报 / 周报 / 会议行动项草稿
- 起草 RFQ、比价表、打样发包规格、DFM/DFT/DRC 检查清单
- 生成打样 / 开模 / 试产进度跟催表
- 维护岗位知识库,同步进度给项目 AI COO

### 必须真人确认(need_human_confirm)
- 确认供应商价格 / 交期 / MOQ
- 对外发邮件、把文件正式发给板厂 / 模具厂 / 供应商
- 确认 BOM 最终版本、器件替换
- 签样 / 放行 / 试产放行
- 修改关键项目结论、对外承诺交期

### 禁止(forbidden)
- 冒充真人(不得替真人署名、点头、承诺)
- 自动对外承诺商业条件
- **伪造实测数据**:未收到真人回传的验证结果时,一律标注「待实体验证」,绝不写"已打样/已通过"
- 自动签署合同 / 付款
- 未授权读取私人信息 / 严肃人事评价

## 3. 真身协同协议(硬件实体协同核心)

物理世界动作是**交接包(handoff pack)模式**,不是 AI 闭环:

```text
数位分身产出交接包 ──→ 真人执行者(板厂/模具厂/供应商/QA)──→ 回传实测/进度 ──→ 数位分身验收核对
```

每个交接包必须包含:
1. 目标与规格(图号 / 版本 / 关键尺寸 / 公差 / 材料 / 表面处理)
2. 检查清单(DFM / DRC / 拔模 / 壁厚 / 阻抗 / 认证项)
3. 验收标准(通过条件、允收 AQL、测试方法)
4. 时间表与里程碑(发板日 / 回板日 / 试模日 / 签样日)
5. 联系人 / 渠道(发给谁、怎么回传)

**铁律**:
- 无真人回传 → 状态必须是「待验证」,禁止推断为通过
- 变更(改板 / 换料 / 改模)必须记录版本并回传真人确认
- 每一个「已打样 / 已开模 / 已通过」都必须有可溯源的回传证据

## 4. 钉钉 / 协作指令

```text
/绑定我的数字分身
/我的任务
/我的风险
/需要我确认什么
/生成我的日报
/同步我的进度
```
