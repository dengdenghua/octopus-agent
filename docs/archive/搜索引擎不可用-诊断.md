# 搜索引擎不可用 — 诊断报告

- 诊断线程：`t3B79q5pIF9O5o9JL4zkfb`
- 诊断时间：2026-08-22

## 结论（一句话）

**web_search 被写死在 `./.env` 里用豆包/火山引擎 doubao 搜索（免费 500 次/月），该订阅额度已耗尽/需续费，接口直接返回 `The function is unavailable. Please renew`；代码没有兜底链，所以这一个引擎挂了 = 整个 web_search 不可用。**

这不是代码 bug，也不是网络问题。

## 证据链

### 1. 配置：只配了一个引擎
`.env`（第 20-22 行）注释与配置：
```
WEB_SEARCH_BACKEND=doubao
DOUBAO_SEARCH_API_KEY=<32位密钥，已配置>
```
- `_resolve_backend()`（`runtime/execution/suckers/web_skills.py:159`）按环境变量选后端：`WEB_SEARCH_BACKEND` 显式 = `doubao`。
- Tavily / Brave / Serper / SearXNG 四个备选后端的 key **全部未配置**（`.env` 里只有 doubao）。

### 2. 接口真实报错
线程里 `doubao_api_error` 共出现 22 处，原文：
```
doubao_api_error: The function is unavailable. Please renew
```
代码路径：`_doubao_search()`（web_skills.py:286）→ 请求 `https://open.feedcoopapi.com/search_api/global_search`
→ 响应 `ResponseMetadata.Error.Message = "The function is unavailable. Please renew"`。

说明：HTTP 请求**成功打到了火山引擎接口并拿到结构化 JSON 错误**（不是连接超时/网络拒绝），所以**网络层是通的**，问题在火山引擎侧的订阅/额度。

### 3. 为什么"看起来所有搜索引擎都挂了"
代码只选 **一个** 后端，**失败即返回、不降级不兜底**（web_skills.py 无 fallback 链）。该线程里模型把其它路径也试了一遍，各有各死法，叠加起来像"全挂"：
| 通道 | 结果 | 原因 |
|---|---|---|
| web_search (doubao) | ❌ | 订阅需续费（根因） |
| DuckDuckGo (`ddgs`) | ❌ | 反爬/人机验证 |
| Bing 抓取 | ❌ | 301 / 正文抽取组件未配 |
| RSS / 维基百科 | ❌ | `immune_reject` 策略拦截 |
| 浏览器自动化 | ❌ | 需桌面端 Octopus |
| exec_shell curl | ❌ | 该会话 `network_access: deny` |

> 说明：此前"根因=network_access deny"的判断**不准确**——doubao 调用拿到的是结构化 API 错误而非连接错误，证明搜索出口本身未被网络策略阻断；`network_access: deny` 只影响该会话里的 curl 等命令式联网。

## 修复建议（按优先级）

1. **续费/升级火山引擎 doubao 搜索订阅**（直接解冻 web_search）
   控制台：火山引擎 → 联网搜索/Doubao Search，确认免费 500 次/月额度是否耗尽或试用是否到期，充值或升级套餐。
2. **切换/增加可用后端**（立即可用，无需等火山引擎）
   在 `.env` 设置 `TAVILY_API_KEY` / `BRAVE_API_KEY` / `SERPER_API_KEY` 任一，并把 `WEB_SEARCH_BACKEND` 改过去。
3. **代码层面加兜底链**（治本，避免"一个引擎挂→全挂"）
   `_web_search` / `_resolve_backend` 应在首选后端报错时自动尝试下一个已配置的后端（如 doubao → tavily → ddg），而不是失败即止。
