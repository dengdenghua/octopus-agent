## 🎯 DSH 还未吸收的优势

截至 2026-08-14 晚间,58 节移植点已全部落地,真实剩余差距:

### 生产收口(短周期)

1. **settlement 通知事件桥** — workflow/jobs 结算事件进 journal + 前端时间线
   (当前 jobs 完成通知已走报告车道,但未落 journal 事件桥)
2. **jobs 完成事件进 journal/前端时间线** — 同上,后台任务可见性
3. **quiet/wakeup 独立调度器** — 当前 jobs 复用 subagent 报告车道的
   wakeup/quiet/queued 三态,非独立调度器
4. **jobs 流式输出 + outputLimitBytes 模型面接线** — 注册表已支持,
   模型面截断未接线(当前终态输出,dsh one-shot 亦如此)
5. **detached quiescence drain** — 分离会话的静默排空
6. **replay 跨 writer wildcard** — 会话重放跨 writer 通配

### 生态互操作(中长周期)

7. **ACP (Agent Client Protocol)** — 标准客户端↔agent 互操作(JSON-RPC over
   stdio):对外暴露 server 让 Zed/VS Code/Cursor 直接驱动我们;对内当客户端
   把其他 `--acp` agent 当子代理调。成本:中(有现成实现可参考,桥到现有
   `runtime/protocol` Realtime 即可)
8. **credential references / identity** — dsh 的凭据引用与身份体系
   (我们有 OS Keychain/Fernet 加密存储 + identity filter,缺引用语法与轮换)
9. **e2b 远端 SpillStore** — 云端沙箱 + 远端大输出存储(本地 Spill 已有)

### 判不值得搬

10. **permission-presets** — dsh 只是把 sandbox/mode + approval/policy 打包成
    命名预设 + 会话 pin + 日志,不是角色系统;我们的多角色体系
    (25+ Agent / teams / preset+persona / RBAC)远超它,沙箱档位与 approval
    profile 已吸收
