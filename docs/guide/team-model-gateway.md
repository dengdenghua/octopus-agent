# Echo 团队模型网关

独立网关管理上游模型、发布目录和成员访问权限。Echo 接入后在自己的电脑上执行工具，只有模型请求通过网关。现有官方账号和计费网关保持独立。

## 在 Echo 中管理

更新并重启 Echo 后端、刷新前端，在「设置 → 模型 → Echo 团队网关」打开「管理本机团队网关」，点击「加载 / 启动网关」。默认监听 `127.0.0.1:8333`，共享默认关闭。开启 Echo 登录认证时，该入口要求本机管理员身份。

1. 填写发布标识、显示名称、上游 `/v1` 地址、模型名称和 Key。支持 Chat Completions 与 Responses。现有 Echo 模型热点可作为 Responses 上游，填写其邀请凭证。
2. 保存草稿，再点击「测试并发布」。测试会真实调用上游一次；失败不会发布。修改任意配置会重新变为草稿；编辑时 Key 留空保留原值。发布只代表模型调用测试通过，不证明模型支持所有工具或视觉功能。
3. 开启团队共享。为每位成员选择允许使用的模型、有效期、调用次数和并发上限，创建一次性邀请。
4. 将兑换码和可连接的网关地址交给对应成员。兑换码只显示一次；兑换后失效，网关生成独立成员凭证。
5. 「成员」中可查看次数并撤销成员；「最近用量」提供最多 100 条请求状态。关闭共享或撤销成员会取消正在执行的请求。

暂停模型后不接受新请求，已经接受的请求可以完成。暂停、修改配置和重新发布均不改变模型发布标识。成员的模型授权为创建邀请时选择的集合；新增模型需要新的授权邀请。

## 成员接入

成员打开自己 Echo 的「设置 → 模型 → Echo 团队网关 → 接入团队」，输入网关地址和兑换码，点击「兑换并接入团队」。成员凭证直接保存在 Echo 后端，所有已授权且已发布的模型自动加入模型列表，不需要在浏览器中传递或另行保存长期凭证。关闭页面或重启 Echo 后仍能恢复连接。

兑换前会持久化本次接入的恢复信息。如果网关已兑换但响应在网络中丢失，点击「立即同步」可凭原接入记录恢复；仅持有原兑换码的其他客户端不能重复兑换。该恢复机制需要双方更新到此版本。

后台每轮同步完成后等待 60 秒，再同步已连接团队的目录；模型选择器每分钟刷新，正常连接下界面更新可能需要约 1–2 分钟。发布、暂停、关闭共享及撤销后的目录状态会更新本机受管理的模型。网关不可用时模型从可选列表移除，连接记录保留以便恢复；当前对话仍选择已下线模型时会明确报错，不自动改走其他来源。可以点击「立即同步」手动更新，或「断开团队连接」删除该连接与它的模型。其他个人模型不受同步影响。

接入记录保存在自定义模型文件同目录的 `<文件名>.team-connections.db` 中，包含成员凭证和未完成兑换的恢复信息，需按密钥文件保护。团队管理的模型名称和连接参数由目录同步维护；普通自定义模型仍可独立编辑。此版本尚不提供团队单点登录。

使用现有 SSH 访问权限建立隧道：

```sh
ssh -N -L 18333:127.0.0.1:8333 用户@团队主机
```

成员填写 `http://127.0.0.1:18333/v1`。隧道需运行在成员 Echo 后端所在电脑。远程直连使用部署方提供的 HTTPS 地址；程序不会自动开公网端口或配置证书。

## 独立部署

```powershell
.\.venv\Scripts\python.exe -m runtime.sensing.gateway.team_gateway
```

支持 `--host`、`--port`、`--root`，可在持久在线服务器上运行同一程序。默认状态位于用户目录 `.octopus/team-gateway`：`hotspot.db` 保存模型配置、上游凭证、成员授权和请求记录；`owner.token` 是独立管理员凭证。备份与访问权限应按密钥文件管理。管理面板连接本机默认端口；自定义部署可使用管理员 HTTP 接口。

| 接口 | 用途 |
| --- | --- |
| `GET /admin/status` | 管理员查看模型、成员与请求记录 |
| `PUT /admin/models/{id}` | 保存草稿，Key 留空保留 |
| `POST /admin/models/{id}/publish` | 测试当前版本并发布 |
| `POST /admin/models/{id}/pause` | 暂停新请求 |
| `POST /admin/enabled` | 开关共享，JSON `enabled` |
| `POST /admin/invitations` | 创建邀请：`label`、`hours`、`max_requests`、`models`、`concurrency` |
| `DELETE /admin/members/{id}` | 撤销成员 |
| `POST /join` | 使用 JSON `code` 兑换成员凭证；可携带持久化的 `exchange_key` 恢复同一次兑换 |
| `GET /v1/models` | 成员可访问的已发布模型 |
| `POST /v1/chat/completions` | Chat Completions 转发 |
| `POST /v1/responses` | Responses 转发 |

管理员与成员分别使用自己的 Bearer 凭证，不能互换。管理接口不会回传上游 Key，成员模型目录不包含上游地址或内部模型名。模型协议需与请求接口一致，不进行有损的跨协议转换。

## 限制与验证

- 当前额度按请求次数计，不是套餐百分比、积分或实际费用。已接受的失败请求也计次。请求状态 `forwarded` 仅表示转发结束，不承诺模型任务成功；不保存对话正文。
- 网关不自动重试。客户端可发送独立 `Idempotency-Key`，同一成员的重复标识返回 409，不再次调用或计次。
- 成员最大并发可设 1–8；单进程全局最多 16 个模型请求。以单进程运行，不支持多副本共享并发计数。
- 请求上限 2 MiB，响应上限 16 MiB，总时长 300 秒。只转发必要认证头，不跟随上游重定向。
- Responses 强制 `store=false`，不支持持久会话引用、后台任务、账号文件引用；不提供文件上传、WebSocket 或托管工具接口。
- 已验证兑换响应丢失后的恢复、连接重启持久化、目录暂停与恢复、成员撤销、已下线模型拒绝回退，以及并发编辑期间的发布版本一致性。
- 已验证本机真实 TCP 链路：Echo 原生分发 → 团队网关 → 独立热点 → 模型，包括发布测试、工具调用、工具结果回传、最终回复和撤销。跨机器、长期在线、多副本及充值计费尚未验收或实现。
