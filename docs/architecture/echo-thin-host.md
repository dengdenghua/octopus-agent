# Echo 轻量执行：职责边界与验收

日期：2026-09-08。

Echo 保留任务、身份、权限、记录、共享工具和团队协调，默认把未设置偏好的独立会话交给 OpenCode。Codex 保留为可选执行引擎。本轮完成默认入口和外部执行链路的打磨，减少两处隐含的宿主模型调用，并分离审批服务依赖。原生编排仍保留，不能称为已完成“两引擎替代所有原生能力”。没有测量安装体积、启动时间或空闲内存降低。

## 默认选择与故障处理

匿名免费模型：依据 OpenCode 1.18.29 官方 `provider.ts`，未连接 Zen 时官方进程提供公开免费模型。Echo 现在缺少账号密钥时不注入 API key/provider 凭据配置，并在实际发送前检查官方进程目录中的输入、输出及缓存价格全部为数值零；价格未知或非零即拒绝执行。未安装 Zen 插件时也可使用默认 Big Pickle；更多模型仍由插件目录管理。已有账号凭据仍按当前主体隔离使用，不借用其他用户身份。免费模型的可用性与费率由官方决定，每次进程启动重新核验。

`frontend/src/core/threads/use-execution-engine.ts` 同步计算默认值，不等待网络状态检查，消除了“检查前发送会走 Auto”的时序窗口：

| 情况 | 行为 |
| --- | --- |
| 无保存偏好的独立会话 | 默认 OpenCode，检查中、未配置或查询失败都不自动换引擎 |
| 已保存 Auto / Echo / Codex / OpenCode | 保留原选择 |
| 无保存偏好的团队会话 | Auto；宿主负责分发，模型协调者按成员默认策略选择执行引擎 |
| 无保存偏好的 Codex 专用角色 | Auto，保留角色指定的 Codex 后端 |
| 未启用引擎功能的嵌入页面或认证加载阶段 | 保留 Auto 默认 |
| 获得正式会话 ID | 将实际发送的选择保存到当前账号与正式 ID 下，并固定当前页面的选择 |
| OpenCode 不可用 | 选择器显示原因，允许用户切换；后端拒绝不可用引擎，不探测或回退到 Codex |

默认值在用户明确选择或发送前不写入存储，因此从独立会话切到团队模式时，可以正确重新计算默认值。其他账号与会话不共享偏好。

常规引擎菜单现在只列 OpenCode、Codex 两个执行引擎，以及“自动”路由选项。已有 `octopus` 偏好的会话显示“原生兼容模式”说明，直到用户主动切换；历史执行徽标仍保留当时真实引擎。拓扑模式不再在前端禁用外部引擎，Auto 的模型预览也跟随默认 OpenCode，避免界面仍显示原生或根据代码关键词预选 Codex。25 项选择器与偏好测试通过，覆盖可用性、旧偏好保留及用户主动迁移。

标准本地宿主的实时 API 独立会话 `auto` 与界面一致，跟随 `execution.member_engine`，默认 OpenCode，不再由代码任务启发式改选 Codex。显式引擎与 Codex 专用角色优先，OpenCode 不可用时拒绝启动。模型协调任务也遵循该默认策略。显式原生配置和没有标准配置的旧嵌入式宿主保留兼容路由；独立 CLI 执行入口尚未按此实时 API 路径验收。

OpenCode 的配置就绪检查检查本机程序、模型选择与凭据可读性，不代表云端当前可访问或额度充足；缺少密钥时允许进入官方匿名免费路径。模型 Auto 使用 `big-pickle`，显式模型不静默替换。匿名任务在服务启动后核验实际目录的零费用信息；已连接付费账号时仍尊重用户的模型选择，不是全局“仅免费”开关。模型列表只在 `is_free=true` 时标绿，不用 Zen 连接名推断免费。

## 已减少的重复调用

1. **历史整理**：自动和手动压缩读取持久化执行记录。最近实际执行引擎为 Codex/OpenCode 时，默认使用本地规则摘要，不再挂接宿主 LLM 摘要器。压缩事件仍持久化、保留最近轮次并发送通知。原生会话继续使用其配置的摘要路由；显式自定义摘要器保持原有语义。
2. **网页正文提取**：可信 `ExecutionTask` 携带宿主绑定的引擎信息。Codex/OpenCode 调用共享 `web_fetch` 时，返回有长度上限的 `content`、URL、原问题与 `answer_pending=true`，由当前引擎回答，不创建辅助 LLM 调用。原生调用仍返回辅助模型生成的 `answer`。URL 安全检查、权限限制、提取与浏览器恢复流程保持原有实现。
3. **模型归属**：输入整形识别 Codex 和 OpenCode 的模型所有权，避免原生复杂度路由替换外部模型；日志不再把 OpenCode 错记为 Codex。客户端的预览信息只用于整形，不取代引擎准入检查。

测试证明外部历史压缩的宿主摘要调用数为 0，原生对照为 1；外部网页正文提取不调用辅助模型。这是特定调用路径的验证，不是整个应用的成本或性能基准。

## 审批服务独立注入

`BuiltStack.approval_router` 是独立的宿主服务依赖。标准构建及未指定此字段的旧式手动构建沿用原有路由；可注入独立审核路由，或显式设置 `None` 禁用模型审核。旧的鸭子类型宿主未提供该字段时保留兼容回退。

Codex/OpenCode 以及原生执行的自动审批均从该服务取得审核器。原生执行在审核路由与执行路由相同时保留本轮模型；注入独立审核路由时使用该服务自己的默认模型。缺失或失败的审核仍拒绝需要审核的操作，不降低权限或跳过审核。这个拆分没有把审核请求转发给 OpenCode，也没有消除已启用自动审批的模型费用。

## 后台模型调用策略

`execution.background_model_calls` 独立于前台执行引擎。默认 `null` 跟随成员策略：OpenCode 默认关闭后台宿主模型调用，原生及旧嵌入宿主保留原行为；`true` 明确允许已有后台模型任务，`false` 明确关闭这些任务的模型调用。`BuiltStack.background_router` 支持独立注入，缺省只在策略允许时继承原生模型路由；显式 `None` 不回退到 planner。

当前覆盖记忆摘要、自动进化触发器、伪装实验调度器及 CLI 提示词进化。记忆定时任务继续运行并写入本地规则摘要，模型关闭时不读取 planner。两个自动调度器在装配模型组件前检查策略；自动进化状态返回 `background_model_calls`，实验调度器返回停用原因。CLI 提示词进化在策略关闭时不装配优化器。

前台技能学习与深度反思的文本辅助服务现经 `AuxiliaryModelRouter` 分发：有 OpenCode/Codex 宿主任务时使用同一引擎的无工具子调用，保留身份、权限与截止时间，失败不回退原生模型；原生任务及没有外部任务的后台调用保留原服务路由。OpenCode 工具会话携带宿主解析后的模型选择，避免辅助调用误用原生模型提示。调用仍可能产生模型用量，不等于取消分析工作；实际模型与回执用量单独记录，缺失用量为未知。60 项辅助服务、角色、规划及学习治理回归通过，外部响应使用测试替身。

电脑视觉循环及明确创建的定时任务仍保留各自执行协议。前台辅助服务现在可绑定延迟原生路由，实际调用兼容能力时才构建原生规划器。后台开关不改变自动审批设置，不代表已启用的审核模型免费。

## 导入装配已按需加载

最新默认 OpenCode 库运行栈已延迟创建原生兼容规划器：没有学习预加载、后台模型启用或模拟模型时，装配只保留工厂；四个并发首次访问只构建一个实例。显式原生配置及预加载仍立即构建。相同 329 项技能的三次样本均确认原生规划器未创建，总耗时中位数约 1.360 秒、工作集约 91.781 MiB。以下各项为前序测量，完整 Web lifespan、桌面启动及安装体积仍待单独测量。

Web 装配复查发现库测量之外的提前访问点。项目、Wiki、实时历史压缩及辅助技能绑定已统一使用 `native_model_services`，获得延迟路由及配置模型；历史压缩现在读取规划器实际的 `planner_model` 字段。Wiki 路由挂载、文档读取及无内容查询验证不创建原生规划器，有内容的模型回答才触发一次构建。原生临时角色也推迟到实际调用时解析模型，修复不完整模型配置导致项目应用无法启动的问题。

本轮 65 项延迟服务、后台策略、Wiki、压缩及轻量宿主测试通过；扩大检查最初暴露上述临时角色启动错误，修复后 31 项应用成员装配、项目 hooks、Wiki 路由及外部临时角色测试通过；新增原生延迟调用断言后的临时角色定向测试为 7 项通过（与前组有重叠）。模型调用使用替身。完整 Web 启动仍有明确待处理路径：`_app_routers.py` 的运维规划器注入、`_app_collab.py` 的手机桥接，以及启用账号网关时 `_app_fallback_routers.py` 的调度器设置。不能把库运行栈数字作为 Web 已完全延迟加载的证明。

后续启动路径修正：DAG 调试器没有使用其兼容 `planner` 参数，应用不再为该注入读取规划器。手机桥接通过 `make_stack_decision_engine` 在收到任务时才获取当前规划器，沿用已有图到设备工具调用转换及无规划器时的空决策行为。账号网关配置通过 `configure_native_planner` 延迟回调，在原生实例向首个调用者发布前完成；已经创建的规划器立即应用配置。链接存储、网关模型和自配模型 fallback 均保留，不更改账号身份或计费选择。40 项延迟规划器、手机转换、权限及移动集成回归通过；Ruff 和项目约束检查通过（0 error、0 warning），无线上模型调用。前段待处理项中的手机与网关绑定已修正，运维状态读取和显式学习操作仍需拆分后才能验证完整 Web 启动。

## 当前代码证据与保留边界

### 模型协调与宿主调度

用户通过 `serve_mesh=0/false/no/off` 明确选择顺序集群时，或没有逐轮选择且 `OCTOPUS_SERVE_MESH` 禁用蜂群时，入口直接进入团队拓扑，不生成随后丢弃的蜂群图。逐轮选择仍优先于环境配置；自动和强制蜂群保留规划行为，由本轮绑定引擎生成任务图。

蜂群规划与执行工作线程现沿用宿主的同一个不可变任务及可信会话，不再由普通请求上下文重建权限。线程池为每个并行成员复制独立的 Context，保留任务、会话及取消上下文；错误线程、身份或请求绑定在规划前拒绝。蜂群分配预算取原规模预算与宿主目标的较小值，并在进入规划和执行阶段检查原任务截止时间；这不表示可以强制终止任意 Python 工作线程。前序 77 项蜂群与团队桥接回归包含真实三线程同步验证。

蜂群 Auto 跟随宿主默认 OpenCode，显式 Codex/OpenCode 也保留所选引擎。外部规划使用无工具的独立角色调用，只提供当前角色经共享工具服务筛选后的工具目录；返回图必须通过工具名、节点数量、依赖存在性、自引用和循环检查，嵌套参数中的引用也计入依赖。Echo 继续执行图调度和工具权限检查。外部规划失败直接报错；拓扑不存在和蜂群异常的恢复使用绑定模型，不切换原生模型。171 项相关回归通过，包含真实蜂群调度器、线程与临时文件读取，模型响应为测试替身。

由于团队模式在上下文装配后确定，外部协调者会恢复用户在原生复杂度路由前的模型选择，防止宿主便宜模型被发送给 Zen。OpenCode 角色指令允许使用宿主公布的委派工具，同时禁止内置子代理。工具事件现在保留有大小上限的结构化输入，并将失败映射为宿主的 `status=error`；团队任务图能读取真实委派参数，失败工具不会被记录为成功委派。

### OpenCode 成员执行服务

`runtime/execution/opencode_roles.py` 现在供实时对话和成员执行器共用，管理角色指令、宿主 MCP、官方进程、流式事件和资源清理，不依赖网页会话层。标准本地宿主的 `execution.member_engine` 现默认 `opencode`，已注册且未指定执行后端的成员使用该服务；角色 profile 的 `capabilities.execution_backend` 明确值优先，可指定 `opencode_server`、`codex_app_server` 或 `native`。全局显式配置 `member_engine: octopus` 保留原生兼容路径。共享部署未配置该字段时仍默认原生，因为 OpenCode 当前只支持本地运行。没有 AgentConfig 的旧嵌入式宿主保留原生行为。

模型优先使用调用方显式选择，其次 `capabilities.opencode_model`、角色 `model`，最后使用 Zen 的默认模型。显式不匹配的模型报错，不回退原生模型；`use_cheap_model` 不会向外部成员注入宿主原生模型池的选择。未知角色不获得通用工具目录，普通成员的默认 OpenCode 路径要求已注册角色。

临时角色（reviewer、researcher 等）与通过本地定义装配的临时角色现由 `runtime/execution/ephemeral_roles.py` 按同一 `member_engine` 设置执行。标准宿主在启动时注入该运行器，OpenCode 工厂不读取原生 planner。角色的既有系统提示、对话与允许共享的记忆继续进入指令；基础工具继承、黑板工具补充和只读筛选复用原有 `select_tool_specs`，并排除临时角色不允许使用的长期记忆工具。

筛选后的工具名作为 Python 参数传入工具目录生成器，在排序和数量裁剪前应用上限。插件激活、完整工具模式或动态工具授权不能越过这个上限；空集合保持无工具语义。临时角色的文本与工具事件通过既有子任务事件通道回传，保留工具参数和成功状态。原生兼容配置仍使用原运行器，没有模型路由的静态宿主保持“未配置”错误，不影响启动。自定义定义中显式指定的模型仍须与选择的引擎兼容，不自动转换供应商模型。

成员任务继承宿主已验证的账号、租户、权限上限、绝对截止时间和审批服务。生成的子任务提示不会替代原始用户授权意图。已有子任务沿用自己的执行坐标，直接派发则分配新子任务坐标，避免复用父任务的 OpenCode 会话。可序列化的成员 context 不能指定身份或扩大工作区权限。

群聊短回复走无工具模式，不启动 MCP；需要工具的成员仍使用宿主授权目录。OpenCode 分支在原生群聊回复和规划器依赖检查之前选择，因此仅使用外部成员的宿主不必提供原生 planner/runtime。同步成员入口要求在工作线程调用，避免阻塞负责审批通知的网页事件循环。

同一引擎状态目录的执行通过跨线程锁串行化，取消或完成后释放锁条目。超时转换为宿主截止时间异常；流式取消在同步工作线程边界转换为宿主取消异常。实时适配层继续负责历史交付标记、心跳和统一消息收尾。

### Codex 群聊成员

明确指定 Codex 的成员在群聊回复模式下继续走 Codex，不再进入原生模型的直接回复分支。后端禁用、执行失败或成功事件没有附带回复文本时均报错，不生成虚假的完成回复，也不切换引擎。

`CodexExecutionRequest.tool_free` 是内部请求字段；无工具请求不允许同时携带动态工具、工具处理器或 App 选择。角色构建跳过宿主工具代理与自动审核模型，清空 App 选择，使用只读模式。在 thread/start、thread/resume 和 turn/start 中显式提交 `environments=[]`，关闭 Codex 内置执行环境。普通任务继续省略该字段；客户端或安全上下文中的任意环境 ID 仍不会被转发。

无工具请求使用独立的私有状态命名空间，外部任务身份保持不变，避免先前的空环境选择污染后续工具任务。账号模式的模型配置直接由 Codex 账号偏好解析，不再为取得未使用的系统默认值读取原生 planner。明确选择跟随系统模型的配置仍保留原来的代理路由逻辑。

## 仍需保留的能力与完整替代条件

CLI `code` 与裸任务入口的新会话现在默认 OpenCode，`--engine octopus` 保留原生兼容路径。模拟响应明确使用原生测试路径；有旧记录的会话保留原引擎，新记录保存引擎、实际模型、历史和失败原因。OpenCode CLI 只装配共享工具，不创建原生规划器；宿主负责工作区权限、审批、预算目标和 `--timeout` 截止时间。`--max-iterations` 仍只控制原生循环。OpenCode 的 `acceptEdits` 需要独立审核服务，目前 CLI 未配置该服务时明确失败，不暗中调用原生审核模型。CLI `run` 图执行仍需处理，不能将代码入口接通当成所有命令已统一。

`runtime/platform/ui/_app_stack.py` 仍装配兼容原生任务的成员运行器、深度进化路由、技能学习路由、电脑视觉循环及条件启用的后台任务；`runtime/cli_serve.py` 还包含记忆整理任务。它们不能因为对话默认改为 OpenCode 就被视为已经迁移或免费。模型协调者已支持 OpenCode；项目、群聊分发和拓扑仍由宿主驱动，其后续阶段和辅助模型服务还需继续拆分。显式自定义的运行器注入和远程 partner 后端仍由其调用方管理，不受默认工厂替换。

完整替代仍需：把这些依赖逐项改成独立服务或按需装配；让团队协调器通过统一接口派发外部成员；验证成员身份隔离、取消传播、失败恢复和共享记录；随后才移除没有调用者的原生循环和依赖包，并测量真实启动、内存与安装体积。保留此边界是为了避免把默认入口调整误报成整个内核已重写。
