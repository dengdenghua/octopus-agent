# 企业协作主链规划（Enterprise Collaboration Roadmap）

> 目标：让 Octopus 从「个人 Agent 工作系统」升级为「同时连接个人电脑、本地数据和企业团队的 Agent 工作系统」。
> 本文件是主链建设的蓝图与对齐基线，任何页面扩张、功能补丁都不得优先于本文件定义的主链。
> 定位对照：**Octo 是企业 Agent 协作网络；Octopus 是同时连接个人电脑、本地数据和企业团队的 Agent 工作系统。**

---

## 1. 战略判断：不跟 Octo 比「Agent 更聪明」，比「协作基础设施更完整」

Octo 的优势不在模型能力，而在企业协作基础设施已成体系：组织权限、频道 ACL、Agent 身份、实时消息分发、管理后台、部署运维。

我们已有的智能体能力并不弱——Agent、技能、记忆、并行任务、本地数据库、自动化和执行工具。真正的差距集中在这五层：

| 层 | 能力 | 现状（代码层面） | 差距 |
|---|---|---|---|
| 1 | 企业身份 | 租户 / 组织 / 部门 / 成员 / Agent 统一身份 | 目前身份是单机 `Identity.find_identity` + JWT 板级，无组织树 |
| 2 | 协作空间 | 频道 / 群聊 / 话题 / 共享文件 / 多人实时状态 | 现有 `channels_router` 是 IM 渠道接入，非企业协作空间 |
| 3 | 权限治理 | 空间权限 / 数据范围 / 工具权限 / 审批 / 密钥隔离 | 有 `trust_engine` 语言级信任，但缺组织级 RBAC 与数据范围 |
| 4 | 可审计性 | Agent 做了什么 / 谁批准的 / 引用了什么数据 / 能否回滚 | 有 `audit_chain` HMAC 链，但未覆盖权限变更与审批取证 |
| 5 | 工程可靠性 | 消息持久化 / 断线恢复 / 幂等 / 任务接管 / 监控与高可用 | 有 `react_resume` 断点恢复，但缺企业级消息与多实例 |

> 结论：只要停止扩张次要页面，集中补齐「身份 — 频道 — 权限 — 审计 — 可靠性」这条主链，就有机会赶上；本地执行能力会形成 Octo 较难复制的差异化。

## 2. 双空间架构（Dual Space Architecture）

### 2.1 设计原则

- **本地空间**：保留现有本地数据库、应用控制、个人记忆与隐私能力，专属于个人。
- **企业空间**：新增组织、频道、共享知识库、多 Agent 群聊与审计，面向团队。
- **同一套成员模型**：Human 与 Agent 使用同一套成员身份，但 Agent 额外绑定工具权限、数据范围和预算。
- **数据隔离**：个人记忆默认不进入企业空间；共享内容必须明确授权后方可进入。

### 2.2 架构分层

```text
┌─────────────────────────────────────────────────────────────┐
│                    企业空间（Enterprise）                      │
│   组织 / 部门 / 频道 / 群聊 / 共享知识库 / 审计 / 审批          │
├─────────────────────────────────────────────────────────────┤
│                 统一成员模型（Human + Agent）                  │
│       身份 · 权限 · 数据范围 · 预算 · 密钥 · 审计轨迹           │
├─────────────────────────────────────────────────────────────┤
│                    本地空间（Local）                          │
│   本地数据库 · 应用控制 · 个人记忆 · 隐私 · 本地执行            │
└─────────────────────────────────────────────────────────────┘
```

### 2.3 与现有模块的映射

| 规划概念 | 现有基础 | 缺什么 |
|---|---|---|
| 企业身份 | `runtime/safety/auth/identity.py`（单机 JWT） | 组织树 / 租户 / 部门 / 成员 / Agent 统一目录 |
| 协作空间 | `sensing/gateway/channels_router.py`（IM 渠道） | 企业频道 / 话题 / 共享文件 / 多人实时状态 |
| 权限治理 | `safety/auth/trust_engine.py`（语言级信任） | 组织级 RBAC / 数据范围 / 工具权限 / 审批 / 密钥隔离 |
| 可审计性 | `safety/audit/audit_chain.py`（HMAC 链） | 权限变更 / 审批取证 / 数据引用溯源 / 回滚 |
| 工程可靠性 | `core/cerebrum/react_resume.py`（断点恢复） | 消息持久化 / 幂等 / 任务接管 / 多实例高可用 |
| 团队拓扑 | `sensing/gateway/organizations_router.py`（拓扑演进） | 从「拓扑建议」升级为「真实组织 + 权限」 |

## 3. 五层依赖链

本文件严格按依赖顺序推进，先打通下层，再叠上层，避免返工。

```text
① 企业身份（租户/组织/成员/Agent 统一目录）
      ↓
② 协作空间（频道/群聊/话题/共享文件）
      ↓
③ 权限治理（RBAC/数据范围/工具权限/审批/密钥）
      ↓
④ 可审计性（Agent 行为/审批/数据引用/回滚）
      ↓
⑤ 工程可靠性（持久化/幂等/任务接管/监控/HA）
```

> 指导原则：①不成立，②无意义；②不成立，③无处落地；③不成立，④不可信；④不成立，⑤无价值。

## 4. 三阶段实施计划

### 阶段一：主链地基（6–8 周）

**目标**：企业空间可被真实使用——至少一个组织、若干频道、Agent 与 Human 同群聊、消息可持久化、基础权限生效。

| 交付项 | 说明 | 验收标准 |
|---|---|---|
| 组织 / 空间 / 频道模型 | 租户、组织、部门、成员、Agent 统一目录 | 创建组织，加入成员，挂载 Agent |
| 成员模型 | Human 与 Agent 统一身份，Agent 附带权限/预算 | 同一身份体系可查 Human 与 Agent |
| Agent 群聊 | 频道内 Human + 多 Agent 协同对话 | 群聊消息可分发、可回放 |
| 持久化消息 | 消息 per-channel 落盘，可恢复 | 重启后消息不丢 |
| 基础权限 | 空间级成员可见性、频道 ACL | 非成员不可见频道内容 |

### 阶段二：协作深化（8–12 周）

**目标**：企业空间具备可信协作与可追溯能力。

| 交付项 | 说明 | 验收标准 |
|---|---|---|
| Agent 指派与接力 | 任务在 Agent 间流转、可接管 | 任务可暂停/移交/恢复 |
| 共享记忆 | 授权后的共享知识库，跨成员可检索 | 只有授权内容可被检索 |
| 审批流 | 高风险动作（外发/密钥/删除）需审批 | 审批记录完整可查 |
| 审计日志 | 覆盖权限变更、审批、数据引用 | 每次关键动作可溯源 |
| 断线恢复 | 消息/任务断线重连后无缝续接 | 断网重连后状态一致 |

### 阶段三：企业级就绪（3–6 个月）

**目标**：可交付给企业客户。

| 交付项 | 说明 | 验收标准 |
|---|---|---|
| SSO | 对接企业身份源 | 企业目录一键登录 |
| 管理后台 | 组织/成员/权限/配额可视化 | 管理员可完成日常运维 |
| 配额计费 | 按租户/成员/Agent 计量 | 用量可统计、可设定上限 |
| 多端 | 桌面 / Web / 移动一致体验 | 多端状态同步 |
| 备份与高可用 | 数据备份、多实例、故障转移 | 单实例故障 30s 内恢复 |
| 企业部署 | Docker / K8s / 私有化 | 一键私有化部署 |

## 5. 关键技术挑战与对策

### 5.1 权限治理是最大耗时点

- **挑战**：空间权限、数据范围、工具权限、审批、密钥隔离交叉，一致性与边际用例极易出错。
- **对策**：先做「最小空间级 RBAC」，再逐层加数据范围与工具权限；权限判定收敛到单一决策模块，杜绝散落判断。

### 5.2 状态一致性

- **挑战**：多 Agent 群聊、任务接管、断线恢复需要跨进程一致。
- **对策**：复用现有 `react_resume` 断点恢复范式，推广到消息与任务；关键写操作幂等化。

### 5.3 审计可信度

- **挑战**：审计必须真实可追溯，不能被自由写入。
- **对策**：复用 `audit_chain` HMAC 链，扩展覆盖权限变更、审批、数据引用；审计写入走统一入口，禁止旁路。

### 5.4 数据隔离

- **挑战**：个人记忆默认不进入企业空间，共享内容必须显式授权。
- **对策**：双层作用域——本地空间私密、企业空间需授权；检索时按作用域过滤，杜绝越权。

## 6. 资源与节奏

- **5–8 名稳定工程人员**：约 3–4 个月可做到有竞争力的企业协作 Beta；6–9 个月接近可交付版本。
- **不要「边做 UI 边补功能」**：企业协作最耗时的是权限、状态一致性和可靠性，不是页面数量。
- **停止扩张次要页面**：把「身份—频道—权限—审计—可靠性」主链置于页面扩张之前。

---

## 7. 一句话定位

> Octo 是企业 Agent 协作网络；Octopus 是同时连接个人电脑、本地数据和企业团队的 Agent 工作系统。

本地执行能力是差异化护城河，企业协作主链是可交付的入场券。两者合一，才能形成 Octo 较难复制的竞争势能。
