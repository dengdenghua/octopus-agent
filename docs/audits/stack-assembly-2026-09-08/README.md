# OpenCode 默认运行栈装配基准

日期：2026-09-08。样本来自三个独立 Python 进程，未调用模型。

配置为 `AgentConfig(enable_web_skills=True, planner=PlannerConfig(type="llm", model="claude-sonnet-4-6"))`，默认成员引擎 OpenCode，初始基准仍创建原生兼容规划器；后续延迟构建结果见文末。账号及数据目录隔离在临时目录中。没有启动网页服务、桌面窗口或模型进程。

工作集由 Windows `GetProcessMemoryInfo` 读取。模块数均为 1179。此处是当前版本基准，不能据此声称整体应用已经降低多少内存或启动时间。

独立的 `profile.json` 使用 cProfile，包含计时开销，不纳入前三个样本。主要发现：

- 导入和模型类构建占显著时间；原生规划器导入也会触发 memory 包的广泛导入。
- 技能注册进行了 107 次验证、123 个测试用例，累计约 0.325 秒。
- 启动测量中会话搜索数据库被打开，导致 Windows 进程退出前无法完整清除临时数据。

首次探测因测量脚本依赖未安装的 psutil 失败，不属于有效样本；随后改用 Windows 原生内存 API。下一步应检查内置技能注册的测试执行与数据库生命周期，同时保留动态技能的验证要求。

五个进程都已结束。对五个具名测试目录的后续递归清理被自动审批以 `blocked by policy` 拒绝，未换用其他方式删除；`.codex-run/stack-profile-*` 的这些残留仅含本次隔离测试数据。有效样本的具体目录记录在各 JSON 的 `scratch_directory` 字段，首次失败目录为 `stack-profile-oy6vpps6`。

原始数据见同目录 `sample1.json`、`sample2.json`、`sample3.json` 和 `profile.json`。

## 历史检索注册自检修正

定位到 `history_search` 的注册测试会执行真实空查询，在注入应用会话库之前创建 fallback store。已移除这个会访问用户数据的启动探针，正常查询仍由注入内存 ThreadStateStore 的测试验证；无副作用参数校验继续通过严格注册验证。新增测试要求注册过程不能调用 store resolver，20 项历史技能测试通过。

修正后的三个独立样本见 `after-history1.json` 至 `after-history3.json`：技能数仍为 329，模块数从 1179 降为 1171，工作集中位数约 99.371 MiB，总时间中位数约 1.705 秒。时间没有显示改善，不能宣称启动加速；本次主要修正是消除启动时读取用户历史及创建搜索数据库的副作用。三个新样本的临时目录均由测量脚本正常清除并核验不存在；此前被拒绝清理的五个旧目录没有重试删除。

## 内存模块兼容导出的按需加载

`runtime.memory` 过去为提供旧模块别名而提前导入诊断、学习、技能库和用户服务，现改为在访问对应别名时加载原模块。92 项导入、配置、历史和辅助模型测试通过，冷进程验证单纯导入 memory 不加载其子服务，旧别名仍返回原模块对象。

同配置的新样本见 `after-memory1.json` 至 `after-memory3.json`。技能数仍为 329，模块数降到 1129，工作集中位数约 98.152 MiB，相比上一组约减少 1.22 MiB；总时间中位数约 1.739 秒。样本数量有限，时间变化没有证明加速，本项收益主要是缩小导入边界。完整网页与桌面启动性能仍不能从此推断。

## 原生兼容规划器延迟构建

默认 OpenCode、非模拟 LLM 且没有启用原生学习预加载或后台模型调用时，运行栈保留线程安全的构建工厂。实际访问 `stack.planner` 或调用原生路由时才构建；类型配置检查和辅助服务绑定不触发构建。显式原生、模拟规划器及上述预加载配置保留原行为。

三个独立进程的新样本见 `after-planner1.json` 至 `after-planner3.json`，均验证 `native_planner_created=false`，仍注册 329 项技能，加载 1041 个模块。导入与装配总耗时中位数约 1.360 秒，工作集中位数约 91.781 MiB；相比上一组分别减少约 0.378 秒和 6.371 MiB。这是少量库运行栈样本，不能等同于完整桌面启动、常驻内存或安装体积改善。新临时目录均已核验不存在。没有发起线上模型调用。

最终验证：`test_deferred_planner`、`test_config`、`test_background_model_policy`、`test_thin_host` 和 `test_app_config_endpoints` 共 107 项通过（147.17 秒）。覆盖首次调用、四线程并发、原生及模拟配置、显式后台服务和学习预加载兼容，以及配置接口回归。Ruff 检查和格式检查通过；项目约束检查为 0 error、0 warning。未重启用户服务或发布安装包。
