# Echo 优化后复查：下一轮机会

日期：2026-09-07。范围是角色资料下半区、新任务页、运行设置菜单；截图均为本轮浏览器现场采集并保存后重新读取检查。本轮未修改产品代码或用户配置。

## 判断

基础视觉已较统一。下一轮更高的收益来自减少理解和寻找操作的成本：把常用动作说清楚，把配置关系组织清楚，把角色展示中的工作信息放在更容易找到的位置。

## 1. 角色资料下半区：有辨识度，内容与操作仍偏密

![角色资料](<D:/echo agent/docs/audits/visual-followup-2026-09-07/01-role-profile.png>)

可保留：角色插画、主题感知的信息区，以及统一的标题与关闭位置。

观察：用户当前滚动位置展示背景档案、性格、立绘关键词、行动边界；底部配置并列出现“基础 / ARM / Skill / 权限”，基础的次级说明被截断。工作设置与角色内容仍在争夺有限空间，ARM 等术语还需要用户理解。

建议（P2）：默认突出职责、适合任务和可用能力，把背景故事和立绘生成材料折叠或放到独立页签。把 ARM 等技术术语放在详细说明中，主入口使用明确的操作名称。让配置入口拥有稳定宽度和清楚的层级，同时保留角色艺术内容。

可访问性风险：截断的可见说明增加理解成本；截图不能证明读屏和键盘流程完整可用。

## 2. 新任务：结构清爽，次级操作的用途不够直观

![新任务](<D:/echo agent/docs/audits/visual-followup-2026-09-07/02-new-task.png>)

可保留：输入框宽度、留白、清楚的角色名称，以及工作区与模式的独立状态行。

观察：灯泡和滑杆式图标缺少常驻文字标签；模型名、模式、权限和引擎分布在输入框内外。可以看见可点的控件，但首次使用时难以直接判断各自改变什么。

建议（P1）：保持输入区安静，将引擎等运行选项组织为有短标签的统一入口。模型与工作区保留易访问位置，其他选项逐步展开。按钮图形可以保持小巧，点击区域保持足够大小。空白页可尝试少量贴合当前角色的示例任务，实际是否保留应通过使用反馈验证。

可访问性：DOM 中图标控件已有可访问名称，这是优点；可见短标签还能帮助不使用读屏的普通用户理解。

## 3. 运行设置：说明可读，选择结果还可更清楚

![运行设置](<D:/echo agent/docs/audits/visual-followup-2026-09-07/03-run-settings.png>)

可保留：“自动 / Echo / Codex”各有用途说明；Escape 可以关闭菜单并将焦点返回入口，实测正常。

观察：菜单展示路由规则，但当前引擎、模型来源与模式的关系还需要用户综合多个控件理解。“自动”选中状态由文本勾号表示；DOM 使用普通 menuitem，没有 aria-checked、aria-selected 或 aria-current。

建议（P1）：用一条简短摘要说明当前运行配置，自动模式继续明确它是发送后决定路由。将单选菜单实现为符合单选语义的控件，向辅助技术暴露选中状态；视觉上可采用选中底色与状态文字，遵循已有视觉规则。

## 后续验证

长任务进度、自动重试、安装失败恢复、满数据列表、200% 缩放及完整键盘/读屏流程值得继续检查。本轮没有运行任务、安装插件或测这些状态，因此不把它们列作已确认缺陷。

优先顺序：新任务与运行设置 → 角色资料的信息分层 → 带真实任务数据的状态走查。
