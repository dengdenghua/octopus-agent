# Echo 前端视觉走查与优化方向

本轮在 1094×912 的当前网页中查看五类代表页面，截图均在本轮采集、保存并重新读取检查。它是一次整体视觉抽查，不是对全部窗口的新一轮完整验收。没有修改产品代码、偏好设置、角色配置或业务数据。

## 判断

有明显优化空间。主工作区的安静感、角色辨识度和项目页清楚的空状态值得保留。主要问题是不同页面的视觉规则尚未统一：常用操作偏小、灰阶层级弱、部分页面边框太多、强调色混用、角色展示与工作界面的风格跨度较大。

下一轮应先确定一套视觉基线，再改共用组件。逐个按钮试样式会在可发现性、点击范围和视觉轻重之间反复摇摆。

## 走查步骤与截图

### 1. 新任务页 — 结构清爽，常用操作偏小

保留舒适的输入宽度与安静背景。实际 DOM 中，根字号是 15px，但“新建任务”“个人空间”“通用”只有 11.25px；侧栏链接约 13.125px，并带 0.76 透明度。留白很宽，操作却集中为小字与微型控件。建议明确区分任务输入、任务设置和全局导航的层级。

![新任务页](<D:/echo agent/docs/audits/visual-direction-2026-09-07/01-new-task.png>)

### 2. 设置窗口 — 分类清楚，容器层级偏重

窗口、账号摘要、导航、内容区和主题卡片连续套边框，视觉碎片较多。建议保留窗口边界，内容分组主要用标题、留白和必要分隔线，普通设置用统一的“名称—说明—控件”行。打开窗口时观察到焦点位于“退出登录”，后续应检查是否应优先放在搜索或内容标题。

![设置窗口](<D:/echo agent/docs/audits/visual-direction-2026-09-07/02-settings.png>)

### 3. HUB 角色目录 — 功能明确，强调与密度需要收敛

搜索、场景和安装动作可识别。但蔷薇选中色、紫色操作按钮与多种彩色卡片并用；专家卡片较大，说明与标签较小。建议场景保留较大的展示卡，专家目录采用紧凑行或卡片；类别色只用于识别，选中和主操作统一用主题主色。场景横向露出属于目录布局，本轮未将它直接判为溢出缺陷。

![HUB](<D:/echo agent/docs/audits/visual-direction-2026-09-07/03-hub.png>)

### 4. 项目工作台 — 空状态较好，页头需要统一

主按钮突出，说明具体，中央图标和主色一致，可以作为其他空状态的基线。顶部标题、较长副标题和动作挤在很薄的一行；emoji 标识与侧栏线性图标不同。建议将标题、简短副标题和操作纳入统一工作台页头。当前没有项目数据，未评价有项目时的列表、卡片和详情。

![项目工作台](<D:/echo agent/docs/audits/visual-direction-2026-09-07/04-projects.png>)

### 5. 角色档案 — 角色有特色，工作界面的一致性偏弱

立绘与世界观有辨识度，可以保留。浅色工作台进入黑底、荧黄、大写标签的档案时，视觉切换很强。档案左栏的页签、数据卡和能力按钮较密，弱文字在深色背景下不够醒目；关闭按钮位于左栏上方，和设置窗口右上角位置不同。建议个性集中在角色立绘与主题内容，窗口骨架、关闭位置、字号、按钮和表单共享工作台规则。

![角色档案](<D:/echo agent/docs/audits/visual-direction-2026-09-07/05-role-profile.png>)

## 建议的视觉基线

以下是待验证的设计建议，不是已经实施的设置。

| 项目 | 建议 |
| --- | --- |
| 字号 | 正文 14–15px，常用导航与操作 13–14px，辅助说明 12–13px，工作台标题 20–24px；密度选项不应把所有操作一起缩成小字 |
| 色彩 | 暖白/中性灰为底，一个主题主色承担选中与主操作；绿、黄、红用于明确的状态信息 |
| 边界 | 页面靠留白分区，卡片只表达独立对象；减少卡片套卡片及每个动作常驻边框 |
| 按钮 | 主动作有明显底色，次动作轻量，图标按钮保留完整命中区域；视觉大小与点击范围分别管理 |
| 间距 | 以 4/8px 为基础形成明确间距档位；相同菜单、页头和表单使用统一行高与对齐 |
| 图标 | 统一线性图标尺寸和线宽，避免同一导航层混用 emoji、装饰图标和不同风格控件 |
| 弹窗 | 统一标题区、关闭位置、内容滚动和底部操作；减少不必要的嵌套边框 |
| 个性化 | 保留角色内容和立绘特色，外层工作界面保持一致 |

## 实施优先级

1. **P1：字号、灰阶、操作命中区域。** 先解决常用操作偏小和辨识不清，收益覆盖整个工作区。
2. **P1：共用组件。** 统一侧栏、页头、按钮、标签、菜单、设置行和弹窗，避免逐页继续分化。
3. **P2：页面密度与强调顺序。** 优化 HUB 目录与设置页，保留项目空状态的简洁结构。
4. **P2：角色展示与工作内容分层。** 保留角色个性，减少与主工作区的交互差异。
5. 在这些基线稳定后，再逐项验证深色模式、窄窗、触屏与缩放，不先堆叠动效或渐变。

## 范围与限制

- 当前只检查了上述五类页面的可见状态；未覆盖全部设置子页、设计画布、所有已安装工作台和有业务数据时的详情。
- 本轮是浅色主界面与角色自带深色档案的观察，没有切换系统主题、字号密度或浏览器尺寸。
- 小字与深色弱文字是可观察的可读性风险，不能据此宣称全站 WCAG 达标或不达标；仍需对比度、键盘路径、触屏、缩放和屏幕阅读器测试。
- 没有运行模型任务、安装角色、创建项目或修改账户与权限。浏览器已恢复到原新任务页。

建议先用新任务页和设置页打磨统一样板，再推广到其他工作台。
