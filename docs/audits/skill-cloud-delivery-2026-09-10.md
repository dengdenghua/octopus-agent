# 技能云端分发优化

本轮实现独立技能包的生成、发布流程和客户端按需下载。尚未执行远端发布，也未移除本地内置技能。

## 核实结果

- 本地 720 个技能标识是开发仓库库存，不等于安装包内容或已安装技能。
- 当前云商城目录有 178 个条目，不能把 720 个标识直接当作全部已上云。
- 桌面 extraResources 不包含整个扩展源码目录；PyInstaller 仍收集 runtime 的数据资源。
- 旧客户端安装单个技能时下载整个 octopus-skills.tar.gz。

## 本轮改动

- 构建内容包时同时生成独立技能归档，文件名携带内容哈希。
- 目录记录每个归档的 URL、SHA-256 和大小；发布工作流在构建后重新签名最终目录，并上传独立归档。
- 安装器优先只下载所选技能；按内容哈希缓存，使用缓存前复核，损坏时重新下载。
- 哈希不匹配立即中止，继续沿用已有解包路径检查。
- 旧云目录没有独立归档字段时兼容原有整包下载。

## 验证与边界

16 项云目录测试通过；单包构建到安装的端到端本地夹具测试通过。已有 POSIX 文件权限测试在 Windows 不适用，单独排除；运行时 invariant 检查通过。

未上传远端资源、未删除开发源码、未修改核心技能加载策略，尚不能宣称安装包已缩小。下一阶段应先发布并验证 178 个云端条目的独立资源，审计运行时依赖和离线核心清单，再按已发布清单调整打包。不能在云端资源未就绪时批量删除内置技能。

## 第二轮：真实内容发布预演

已在 `.codex-run/skill-cloud-release` 生成全部 178 个独立技能包，目录位于 `.codex-run/skill-registry-preview.json`。没有覆盖已签名的正式目录。验证器逐一检查文件集、文件内容、SHA-256、归档大小，并与兼容整包比对，178 项全部通过。

- 旧整包：8,650,881 字节（约 8.25 MiB）。
- 独立技能包中位数：4,914.5 字节（约 4.8 KiB）。
- 最大独立包：3,971,245 字节（约 3.79 MiB）。
- 安装一个中位大小的技能，相比首次下载整包减少约 99.94% 下载量；这不是安装包体积收益。
- 独立归档固定时间戳和用户元数据，文件内容不变时哈希保持不变，便于缓存复用；重复构建测试通过。

已核实 `runtime/execution/all_skills` 只有 159 个顶层技能包，完整目录树约 11.22 MiB；此前 352 份运行时 SKILL.md 包含嵌套文档，不能按同样数量删除或上传。连接器技能需随依赖包管理，角色私有技能和导入目录也不能无差别自动发布。

本轮仍是本地发布预演，正式发布需使用现有受保护的发布流水线签名及上传。部署前继续保留核心资源和旧目录兼容路径。

## 第三轮：安装到运行时的闭环

修复云商城安装目录与运行时扫描目录不一致的问题：

- 普通安装与流式安装完成后向当前技能注册表注册，并返回 `registered_now`。
- 桌面启动时补充扫描 `data/skills`，重启后无需重新下载；已存在的外部和内置技能优先，不覆盖同名条目。
- OpenCode/Codex 共用的显式技能指令解析器可读取已安装目录，仍受注册表、角色权限和受信路径约束。
- 共享/商业部署继续禁止可变技能目录参与加载。

验证：市场技能、授权与引擎角色上下文 54 项测试通过；云安装 18 项测试通过（Windows 排除既有 POSIX 权限位测试）。新增普通/流式安装即时注册、重启恢复与共享模式边界测试。

正式发布尚未执行：当前终端没有 GitHub CLI，发布依赖仓库 `plugin-content-signing` 受保护环境和签名变量；工作区改动尚未进入远端发布版本。未为了绕过发布环境而手工生成信任密钥或上传未签名正式目录。

## 第四轮：刷新回退与发布顺序

- 刷新先尝试验证远端新目录，不再预先删除本地已验证目录与签名。断网或目录/签名版本暂时不一致时使用已验证缓存，重启后仍可恢复。
- 发布分为内容上传和目录上传两个步骤，内容上传失败时不暴露新目录。GitHub 多个目录/签名资产的替换仍不具备事务原子性，客户端继续验证配对签名。
- 发布互斥键改为目标仓库，避免本仓库不同分支同时覆盖同一目标 release。
- 24 项目录与安装测试通过，包含断网、签名不匹配、成功更新和重启恢复；Windows 仍排除既有 POSIX 权限位测试。工作流 YAML、上传先后顺序与互斥键检查通过。

尚未触发线上发布，也未减少内置资源。本轮核对时工作区有 456 项未提交变更，不能整体混入技能发布；需先整理可发布版本，再通过受保护流水线上传。


## 第五轮：全量本地识别与版本归档

用户要求全部上云，并将本地已有技能显示为已安装。本轮修复安装识别并准备完整本地暂存，不代表已经完成远端发布。

- `/api/agent-market/cloud/installed` 直接扫描本地技能文件，不依赖尚未初始化的统一资产索引；返回去重名称及不含磁盘路径的条目。
- 扫描范围包含仓库 runtime、extensions、skills、agents、.octopus，以及用户 .octopus 安装/导入目录。当前为 753 个大小写去重名称、899 份文件；比历史仅仓库统计范围更广。
- HUB 合并云端和本地同名技能，实测显示 753/753 已安装。这里的安装表示文件存在，不改变角色权限、启用状态或插件依赖。
- 云端目录请求支持 offset 翻页，不再只显示前 500 项。
- `tools/prepare_skill_cloud_inventory.py` 生成完整版本暂存：753 个技能，842 个内容不同的归档，50,381,867 字节。相同 SKILL.md 但脚本不同的版本不会被丢弃。归档逐文件 SHA-256 校验；3 个环境/凭据类文件未打包。
- 暂存清单：`.codex-run/all-skills-cloud-staging/inventory.json`。明确标记 `prepared_not_published`，没有伪造下载 URL，也没有覆盖已签名正式目录。本地副本未删除。
- 暂存使用独立 package_id 保留原始名称和不同来源版本；另生成 skill-registry.candidate.json，将稳定包 ID 与原始显示名/aliases 分开；HUB 按 aliases 匹配本地名称，保留已有分类元数据。753 个候选条目与兼容整包/独立包闭包验证通过；安卓点号命名、文档专家、前端设计 3 个包通过隔离目录安装检查。候选目录仍需正式签名上传，插件依赖与运行权限不因文件上云而自动启用。

验证：本地识别/归档测试 3 项通过，前端技能列表、分页、包名别名与既有生命周期测试合计 12 项通过，前端构建成功；服务已重启，浏览器恢复登录后实测安装数正确。

发布阻塞：当前环境未配置 MARKETPLACE_RELEASE_TOKEN、GitHub token 和 OCTOPUS_PLUGIN_SIGNING_PRIVATE_KEY；本机 Git 凭据无法在非交互方式取得。既有发布目标是 dengdenghua/workbuddy-expert-market 的 octopus-content release，受保护环境为 plugin-content-signing。尚未上传、未签名、未验证远端下载，不能宣称全部上云。
