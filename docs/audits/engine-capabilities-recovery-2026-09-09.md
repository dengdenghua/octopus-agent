# 模型控件与历史恢复打磨

2026-09-09；接续 [CodexHost 研究](codex-host-research-2026-09-09.md) 与 [OpenCode SSE 实现](opencode-sse-2026-09-09.md)。本次沿用 Echo 的引擎适配、宿主权限和事件日志，没有引入 CodexHost 桌面注入层。

## 已实现和核验

- **确认后更新模型。** 输入框与设置页的 Codex 保存操作按用户串行化；输入框在服务端响应前保留原配置，失败显示错误，不发布切换成功通知。后端无缓存时读取原生模型目录，校验模型和推理等级后再保存；保存失败保留原配置。
- **只显示明确支持的能力。** 两类模型菜单和设置页共用推理等级过滤。未知能力、明确不支持或空列表均不展示推理入口。Codex 换模型时不携带前一个模型的专用推理档位。OpenCode 当前适配器未传递原生 variant，因此隐藏该入口；模型默认推理仍由原生引擎决定。权限继续由 Echo 宿主按每轮上下文执行，不仿冒原生权限配置。
- **待处理交互恢复。** 核验已有 detached emitter：断线后，审批和用户提问会在剩余超时预算内重新送达有访问权限的连接；不会重发模型任务。停止期间不会重新弹出交互。这是同一后台进程内的连接恢复，未新增跨进程持久化审批服务。
- **核对后派生。** 先核对聊天快照与事件日志的已结束回合，再原子写入子会话日志。源记录变化、内容不一致或选中活动回合时失败；失败删除仍未被使用的子会话。历史重建不复制活跃审批、原生会话绑定或中断请求。派生会话在同一用户下继承浏览器保存的引擎偏好，之后独立保存自己的选择。
- **编辑与撤销分开。** 修复原本只有事件发布、没有接收的编辑入口：只向当前会话输入框填入草稿，由用户作为新消息提交，不截断原历史、不撤销文件。
- **依据实际修改撤销。** 文件撤销核对执行日志中的文件和补丁，拒绝缺失记录、截断记录、篡改补丁和已经冲突的文件。单个 hunk 的接受/撤销决定持久化，重试已撤销 hunk 不再反向应用。子会话继承的修改只能回到源会话撤销，避免把派生历史当作新的文件操作记录。
