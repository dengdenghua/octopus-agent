# OpenCode 增量接收优化（2026-09-09）

Echo 前端与后端继续通过 WebSocket 通信。本次仅调整后端与本机 OpenCode 的通信：先订阅 `/event` SSE，再提交一次 `/session/{id}/message`，实时转换正文和工具事件。

## 行为

- 健康连接只在提交前和完成后读取完整消息历史，替代原来每 100 毫秒读取历史。终态核对补齐漏掉的正文和工具结果。
- 使用 OpenCode 原生格式的用户消息 ID，通过 sessionID、parentID 和 messageID 限定当前轮次，避免混入其他会话或历史消息；未知 part 不作为正文，推理内容不经正文通道输出。
- SSE 不可用、断开或帧格式无效时，本轮改为最多每秒一次历史读取，不重发任务。下一轮重新尝试 SSE。暂不在同一轮重连，以免无序号增量与快照重叠造成重复文字。
- 事件队列上限 128；单帧累计字符上限 1,000,000；带事件 ID 的重复事件在最近 256 个 ID 范围内去重。未带 ID 的任意重复增量不具备通用去重保证。
- 用户停止或消费任务被取消时，调用原生 abort，并最多等待 3 秒检查 idle。取消过的热进程无论是否确认 idle 都会回收，避免下一轮复用仍可能接收迟到任务的进程。

## 验证

- 117 项相关测试通过：SSE 增量、终态核对、重复事件、断线回退、消息归属、背压关闭、用户停止、外部任务取消、abort 失败后的进程回收，以及现有 OpenCode / realtime 执行回归。
- 三个本次 Python 文件的 Ruff 检查通过。测试输出另有两条既有 websockets 弃用提示。
- 本机原生 OpenCode、独立临时目录、无账号密钥、官方目录验证为免费的 `big-pickle` 实测：输出 `SSE works.`；正文先于提交请求完成到达；历史 GET 共 2 次，任务 POST 共 1 次。
- 单次实测首段约 6.67 秒、完成约 6.73 秒，包含冷启动和模型时间，不能作为模型响应速度提升的对照结论。测试原生进程和临时目录已随上下文退出清理。
