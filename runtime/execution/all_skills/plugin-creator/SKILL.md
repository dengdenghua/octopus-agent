# 插件创建器

将用户需要的能力做成符合目标宿主格式的插件。当前工作区为 Echo 时，默认采用 Echo 的 `plugin.yaml` 与 `ModulePlugin` 格式。用户明确要求 Codex、MCP 或其他宿主时，先读取该宿主的规范，不把不同宿主的清单混用。

## 实现

- 先查看当前项目已有插件、加载器与注册 API，确定所需能力是提示词、可执行工具、连接器还是带界面的应用。复用已有实现；不要为简单提示词引入后台服务。
- 按用户指定位置创建；未指定时在当前工作区的独立插件目录开发。保留已有插件及用户配置，不直接修改默认内置插件来试验新功能。
- 使用 [Echo 插件接口参考](references/echo-plugin.md) 了解最小包结构和生命周期。接口以当前项目源码为准，尤其核对注册方法、处理函数参数和依赖声明。
- 生成实际需要的清单、入口与资源。技能名称使用插件名前缀；配置使用 schema 描述。密钥通过宿主配置或环境变量读取，不写入清单、示例或日志。
- 通过宿主提供的注册接口添加工具、路由与任务，使停用或卸载能清理注册项。停止时关闭连接与后台任务。注册或导入阶段不发起真实外部操作。

## 验证与交付

先检查清单格式、依赖与相对资源路径，再在隔离目录或测试上下文验证导入、注册、典型调用、失败提示和卸载清理。需要外部服务的测试优先使用替身，并明确未验证的真实连接部分。

交付插件路径、能力说明、必要配置和已完成的验证。用户要求安装或启用时走宿主现有安装生命周期，不把文件生成成功描述成已启用。发布或调用会产生外部影响的接口，沿用用户对该操作的授权范围。
