# 阶段交付与验收

读取当前已批准的范围、阶段成员、任务状态、交付物和验收条件。缺少证据时说明缺什么，不凭对话中的“已完成”判断成功。

逐条形成“标准 → 产物或测试证据 → 通过/不通过/待确认”。文件须实际存在且可读；链接须对应真实产物；执行动作须有工具回执。模型自评可辅助检查，不能取代用户验收。

区分当前阶段要求与后续阶段要求：不要因为第二阶段文案还没完成而拒收第一阶段定位简报，也不能把全项目完成条件遗漏到最后。

不通过时列出最小返工项、责任角色、影响和复验方法。涉及扩大范围、预算、权限或增加成员时交给宿主变更审批；原范围内返工按现有授权继续。

## Echo 操作边界

`/project report` 查看状态；`/project accept` 发起阶段验收流程；验收后下一阶段由 `/project run` 继续请求执行。仅在实际接口或用户命令完成后报告状态变化，不通过聊天文本假装调用。

预算暂停先区分费用达到限制、费用回报缺失、任务启动失败。缺失费用不当作零；不要为完成演练擅自关闭限制。工作区权限错误先修复宿主授权目录的一致性，不放大子任务权限。

交接说明包含已验收版本、未解决问题、下一阶段输入、参与角色和授权状态。交付修改后重新核验相应标准，不能沿用旧版本的验收凭据。

本流程目前为待完整实跑验证的指导；不能声称本项目已通过验收，除非当前项目有对应证据。
